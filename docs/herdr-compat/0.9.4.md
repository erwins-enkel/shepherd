## Human triage (added after the run — preserve across reruns)

Zero FAIL, zero REVIEW. `api schema` is byte-identical to 0.9.3, the protocol stays 22,
`gen:herdr-types` and the recaptured fixture manifest (`gen:herdr-fixtures` against an isolated 0.9.4
server, no skipped method) are unchanged, and the CLI reference pages differ only in their version
stamp. 0.9.4's changes on the driven surface sit behind unchanged flags and schemas, so the release
notes were traced by hand. Tracked in #3070.

### herdr #4950 / #4988 — macOS canonical-input guard on `pane run` / `agent.start`

On macOS, `pane.send_input` (what `pane run` uses) and `agent.start` now refuse a submission whose
longest line exceeds the tty's canonical-mode limit, returning the existing input error instead of
silently losing bytes. Raw-mode input and multiple short lines stay accepted.

**Decision: no impact.** Shepherd never types a long line into a shell:

- The CLI driver's spawn (`runInReadyPane` in `src/herdr.ts`) types only `sh '<script>'`, built by
  `spawnCommandLine()` in `src/spawn-script.ts` since #1967. `test/spawn-script.test.ts` pins that
  line below Darwin's `MAX_INPUT` for a full-size (>8 KB) spawn.
- The socket driver types the same short line through `pane.send_text` + `pane.send_keys`. Those
  methods are not guarded.
- `agent start` is only the ≤0.7.4 path.
- Prompts and steers go into the agent's TUI, which runs in raw mode, through `pane send-text` or
  `pane.send_text`.

The probe host is Linux, so this guard was not exercised live. The evidence is the code trace plus
the existing pin. If the line ever grew past the limit, 0.9.4 would reject it with an error rather
than truncate it as before #1967. The bounded `pane run` retry would then surface that error
instead of a silent 30s auto-detect timeout.

### herdr #5143 / #5173 — confirm closing a workspace's only pane

The confirmation covers the TUI keybinding and context menu only. Upstream states that CLI/API
closes remain immediate. **Decision: no impact.** Shepherd closes through `pane close`/`tab close`
(CLI) and `pane.close`/`tab.close` (socket). L5 shows the last-tab close behaviour unchanged
(`closed-workspace-destroyed` on both sides).

### herdr #4920 / #4965 — server ignores SIGHUP

The server now ignores SIGHUP and logs why it stopped. Ctrl+C, SIGTERM and `server stop` still stop
it. **Decision: no impact.** Nothing in `src/` or `scripts/` stops herdr with SIGHUP. The isolated
probe servers stop via `server stop`, then SIGTERM, then SIGKILL.

### herdr #5096 / #5171 — out-of-range workspace number

`worktree list`/`worktree open`/`pane move --new-tab` with a workspace number past the last one used
to crash the server. They now return `workspace_not_found`. **Decision: no impact.** It turns a crash
into an error.

### L7 / L11

L7 reads `done`/`done`: herdr #1716 is still unfixed and `HERDR_LAST_FULL_SANDBOX_STATUS_VERSION`
stays 0.7.4. L11 (`false`/`false`) shows #4687's behaviour carried over unchanged.

### Opportunities (follow-ups, not bump scope)

- herdr now logs one line per shutdown with the reason, including the `server.stop` caller PID and
  its parent (#4965). Shepherd's diagnostics could surface that line when the daemon dies
  unexpectedly.
- herdr's own SIGHUP immunity makes Shepherd.app's SIGHUP-ignoring launch redundant on ≥0.9.4 only.
  Keep it while older versions are supported.
