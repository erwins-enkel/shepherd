## Human triage (added after the run — preserve across reruns)

Zero FAIL and zero REVIEW. The release's only change sits in herdr's own client, behind unchanged
flags and an unchanged schema, so no check above can see it. It was traced to its one Shepherd
consumer by hand and measured A/B.

### What changed upstream (herdr #4751, PR #4759)

v0.9.2…v0.9.3 is three commits. Apart from version stamps and the changelog, they touch only
`src/client/input.rs` and `src/raw_input.rs`, the herdr client's host-stdin framer. The protocol,
`src/api/`, the schema and the CLI are untouched, which is why S1–S4 show no drift. The hotfix
narrows two 0.9.2 input changes that were too broad:

- **Kitty-confirming hosts.** With a host that confirms the kitty keyboard protocol, 0.9.2
  dropped the Escape of ESC-prefixed bindings (`ESC b`, `ESC CR`) and could hold a lone Escape
  forever. 0.9.3 restores 0.9.1 framing and adds only a bounded 500 ms wait for a delayed
  mouse-report tail.
- **Mouse capture on.** An exact `ESC[` now waits 50 ms instead of 150 ms, so Alt+[ followed by
  a fast key no longer merges into one CSI sequence.

### Consumer: the default web terminal (`src/pty-attach.mjs`)

Shepherd's default interactive terminal runs `herdr agent attach <pane> --takeover` under
node-pty and feeds it xterm.js bytes, so xterm.js is that client's host terminal. The socket
terminal (`SHEPHERD_HERDR_SOCKET_TERMINAL`, default OFF) talks to the server directly and never
reaches this framer; L9 covers it.

**Code trace.** `agent attach` runs `run_terminal_attach` → `setup_direct_attach_terminal` →
`setup_terminal_with_capabilities(false, …)`. With client protocols off, the attach client never
sends the kitty query `CSI ? u`, so `host_escape_disambiguation_active` stays false on this path
whatever the host is. xterm.js 6.0.0, Shepherd's version, could not confirm the protocol anyway.
Only the mouse-capture timing branch is reachable.

**Measured A/B.** Setup, identical for both versions:

- an isolated 0.9.2 and an isolated 0.9.3 server;
- a pane running `stty raw -echo; cat > rec.bin`, registered like a sandboxed spawn;
- `herdr agent attach <pane> --takeover` spawned under node-pty with Node, as `pty-attach.mjs`
  does;
- a harness that answers DA1 and OSC 10/11 like xterm.js;
- each case written separately and read back from the recorder after 900 ms.

| Observation                                                             | 0.9.2 | 0.9.3 |
| ----------------------------------------------------------------------- | ----- | ----- |
| attach sends `CSI ? u`, DA1 or OSC 10/11 (all it was watched for)       | no    | no    |
| attach enables host mouse capture (`?1000h` `?1002h` `?1003h` `?1006h`) | yes   | yes   |

| Case (Shepherd source)                                         | Sent (hex)                  | 0.9.2 received | 0.9.3 received |
| -------------------------------------------------------------- | --------------------------- | -------------- | -------------- |
| Esc key (`ui/src/lib/controlKeys.ts`)                          | `1b`                        | identical      | identical      |
| Esc, then `x` after 200 ms                                     | `1b` · `78`                 | identical      | identical      |
| Arrow left / up (`controlKeys.ts`)                             | `1b5b44`, `1b5b41`          | identical      | identical      |
| Alt+Up (Codex questions button, `ViewportTermControls.svelte`) | `1b5b313b3341`              | identical      | identical      |
| Ctrl+End, jump to bottom (`Viewport.svelte`)                   | `1b5b313b3546`              | identical      | identical      |
| Alt+b / Alt+f (xterm.js Meta = ESC prefix)                     | `1b62`, `1b66`              | identical      | identical      |
| Alt+Backspace (`ESC DEL`)                                      | `1b7f`                      | identical      | identical      |
| Shift+Enter (Shepherd sends LF, `Viewport.svelte`)             | `0a`                        | identical      | identical      |
| Enter                                                          | `0d`                        | identical      | identical      |
| `ESC[`, then `a` after 80 ms (the retimed branch)              | `1b5b` · `61`               | identical      | identical      |
| `ESC`, then CR after 40 ms                                     | `1b` · `0d`                 | identical      | identical      |
| Plain text                                                     | `616263`                    | identical      | identical      |
| Bracketed paste                                                | `1b5b3230307e…1b5b3230317e` | `hello` only   | `hello` only   |

The paste markers are stripped on both versions because the recorder never enabled
bracketed-paste mode (`?2004h`). That is normal terminal behaviour, and it shows the recorder
does register transformations.

**Control.** Under the same harness, herdr's main TUI client does send `CSI ? u`, DA1 and
OSC 10/11 on both versions, which confirms the trace: only `agent attach` skips the kitty probe.
Byte delivery through the main client was not measured. It opens on its machine picker, and it is
not a path Shepherd drives.

**Decision: accept.** On every path Shepherd drives, 0.9.3's input handling is byte-identical to
0.9.2's. Shepherd also never emits the #4751 bindings as its own chords: Shift+Enter goes out as
LF, and Alt+[ / Alt+] are swallowed as session-switch chords (`altComboKey`) before they reach the
PTY.

### Fixtures, CLI reference and floors

- **Schema and types:** regenerating against the 0.9.3 binary leaves
  `src/generated/herdr-schema.json` and `src/generated/herdr-protocol.ts` byte-identical.
- **Fixtures:** `gen:herdr-fixtures` against an isolated 0.9.3 server with a populated workspace
  captured the same four methods with identical `type` and `resultKeys` and skipped none, so the
  committed manifest is unchanged.
- **CLI reference:** the regenerated pages differ only in their version stamp.
- **Floors unchanged:** L7 still lands `idle` on `done`, so `HERDR_LAST_FULL_SANDBOX_STATUS_VERSION`
  stays 0.7.4. The external-registration (0.7.5) and first-pane-control (0.7.3) floors are
  untouched. L11 reads `false` on both sides, so 0.9.2's record drop after exit is unchanged.
- **Protocol:** it stayed 22, which is already allowlisted.
