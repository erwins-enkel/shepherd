## Human triage (added after the run — preserve across reruns)

Zero FAIL, zero REVIEW. 0.9.5 is a hotfix for 0.9.4. `api schema` is byte-identical to 0.9.4, the
protocol stays 22, `gen:herdr-types` is unchanged, and the recaptured fixture manifest
(`gen:herdr-fixtures` against an isolated 0.9.5 server, no skipped method) is unchanged. The CLI
reference pages differ only in their version stamp. The release's changes sit in herdr's
agent-detection manifests, its integration assets and the TUI input path, behind unchanged flags and
schemas, so the release notes were traced by hand. Tracked in #3121.

### herdr #5246 / #5278 — Codex turn hooks dropped

`herdr integration install codex` no longer installs Codex's UserPromptSubmit/Stop/Interrupt hooks
(and removes the ones 0.9.4 installed). Codex status comes from herdr's screen detection again, and
`herdr:codex` is a session-only hook source. Upstream reverts #4756, a workaround for idle detection
that 07e3840b had already restored before 0.9.4.

**Decision: no impact.** Shepherd never runs `herdr integration install`. It reads Codex status in two
ways, and neither depends on those hooks:

- A trusted session is unregistered and herdr-detected, which is the screen detection 0.9.4
  already had.
- A sandboxed session reports Shepherd's own derived state under `--source shepherd`
  (`maybePushAgentState()` in `src/poller.ts`).

The branches removed from herdr's `src/terminal/state.rs` match only the `herdr:codex`/`codex`
source pair. The operator's `~/.codex` carries no herdr hooks.

### herdr #4573 / #5192 — blocked Claude questions in named sessions

herdr's Claude detection manifest gains a rule for sessions named with `--name` or `/rename`. Their
session-name divider used to hide the question's controls, so an unanswered question read as
finished. **Decision: no impact.**

- Shepherd's Claude launch passes neither `--name` nor `/rename` (no such argv in `src/`), so its
  panes keep matching the unchanged unnamed rule.
- The change is detection-only: no schema, record or CLI drift (S2–S4).
- L2, L6 and L7 read the same on both sides.

### herdr #5255 — prefix shortcuts sent as plain text

The fix covers IMEs and Ghostty `text:` keybinds that deliver the prefix and the next key as one
text chunk. It lives in the attached TUI client's key handling. **Decision: no impact.** Shepherd
writes into panes through `pane send-keys`/`send-text` (CLI) or `pane.send_text`/`pane.send_keys` and
the socket terminal. None of them passes through herdr's prefix-key handling, and L9's terminal
contract is unchanged.

### herdr #5267 / #5269, #5253 / #5270, #4639 / #5282 — Windows only

The three fixes cover plugin panes vs. a same-named `PATH` folder, Claude session tracking under a
non-ASCII user folder, and `machine add` progress output. **Decision: no impact.** Shepherd runs no
herdr plugins, never calls `machine add`, and the Linux probe host cannot exercise them.

### L7 / L11

L7 reads `done`/`done`: herdr #1716 is still unfixed and `HERDR_LAST_FULL_SANDBOX_STATUS_VERSION`
stays 0.7.4. L11 (`false`/`false`) shows #4687's behaviour carried over unchanged.

### Opportunities (follow-ups, not bump scope)

- Since #5192, launching Claude with `--name <session>` no longer hides an unanswered question from
  herdr's `blocked` detection. Naming Shepherd's Claude sessions (e.g. for `claude --resume`
  pickers) becomes viable only once the supported floor is ≥0.9.5. On older herdr such a question
  would read as finished.
