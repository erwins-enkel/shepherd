## Human triage (added after the run — preserve across reruns)

Zero FAIL, zero REVIEW. 0.9.3 is a hotfix of 0.9.2 whose only change sits behind flags and schemas
the static half cannot see, so it was traced by hand.

### herdr #4751 / #4759 — escape-prefixed key bindings (release notes)

The v0.9.2…v0.9.3 diff touches only `src/client/input.rs` and `src/raw_input.rs`: the timeouts and
disambiguation of `RawInputByteFramer`, which only the attached TUI client uses for the host
terminal's stdin (`for_host_input`, `set_host_escape_disambiguation_active`). `api schema` is
byte-identical and the protocol stays 22.

**Decision: no impact.** Shepherd never feeds that framer:

- `send()` writes to panes with `pane send-keys` / `pane send-text` (CLI driver) or `pane.send_keys` /
  `pane.send_text` (socket driver). This covers the
  lone ESC of halt/interrupt and the bracketed-paste steer + CR in `src/service.ts`. It goes
  straight to the pane, not through a client's stdin.
- The web terminal uses the socket terminal session. L9 (`verify-herdr-terminal.ts`) passes against
  0.9.3.

### L7 — `undetermined` on both sides in the first run (checker bug, fixed)

The isolated servers inherited the operator's `$SHELL` (zsh). With the empty isolated `HOME`, zsh's
newuser-install wizard swallowed the probe's typed `sleep 300`, so the pane stayed an idle shell.
herdr #4687 then dropped the self-reported agent before `--state idle` could be read, on 0.9.2 and
0.9.3 alike. `startIsolatedServer` now pins `SHELL=/bin/sh`. This run shows `done`/`done`: herdr
#1716 is unchanged and `HERDR_LAST_FULL_SANDBOX_STATUS_VERSION` stays 0.7.4. L11 (`false`/`false`)
confirms that #4687's behaviour carried over from 0.9.2 unchanged.
