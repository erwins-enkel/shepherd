## Human triage (added after the run — preserve across reruns)

Zero FAIL. Both REVIEW items (S2, L11) are decided below. After them come the release-note
changes that ride on **unchanged** flags and schemas, which neither S2 nor S4 can see; each was
traced to its consumer by hand.

### S2 — the pane graphics API is gone (herdr #4561)

`pane.graphics.{set,clear,info}` now return `unknown_method`. The `pane_graphics_frame_ack` /
`pane_graphics_info` results and the `PaneGraphicsFormat` enum left the schema, because apps
render images through standard Kitty graphics instead.

**Decision: accept.** Shepherd never used this API:

- The consumer scan (`scripts/herdr-compat/consumers.ts`) finds none of these names as a quoted
  literal in `src/`, `scripts/` or `deploy/` outside `src/generated/`.
- The regenerated `src/generated/herdr-protocol.ts` drops the types and `tsc --noEmit` stays
  clean, so no typed `request()` referenced them either.
- The additions are additive and unconsumed: `resume_argv` on the report_agent pair, `pane.clear`
  and `server.ssh_agent.register`, plus S3's optional `PaneInfo.restore_error` and
  `AgentInfo.completion_seq`.

### L11 — a self-reported agent is dropped once its process exits (herdr #4687)

herdr 0.9.2 clears a **self-reported** agent — hook authority whose `--agent` label herdr does not
recognise, which is exactly Shepherd's sandboxed (bwrap) registration — whenever the pane's own
shell is the sole foreground job again. The check runs about once a second and is not gated on a
transition. Measured on isolated servers:

| Scenario                                                                     | 0.9.1                | 0.9.2                                                                 |
| ---------------------------------------------------------------------------- | -------------------- | --------------------------------------------------------------------- |
| registered agent, then its process exits to the shell                        | kept (status frozen) | dropped within ~1–4 s; tab `agent_status` → `unknown`, tab label kept |
| registration while the shell is still idle                                   | kept                 | dropped within 0.3 s, and stays dropped once the command starts       |
| Shepherd's real order (`pane run` / `send_text` + Enter, then register), 52× | 0 dropped            | 0 dropped                                                             |
| a recognised agent (herdr-detected, i.e. a trusted spawn) after its exit     | dropped              | dropped                                                               |

Consumer trace:

- **User sessions.** After a sandboxed claude exits, the tick matches no agent, so `reapGone` sets
  the status to `done`. 0.9.1 ended on `done` too, via the pushed `idle` landing on `done` (#1716).
  - Liveness stays `husk`, because `isStranded` needs a matched agent, so auto-revive never fires.
  - No state push goes out, since nothing matched.
  - The husk can no longer be PTY-attached, and resume respawns instead of adopting a dead record.

  This is what trusted sessions already did on 0.9.1. It is pinned in
  `test/poller-report-agent.test.ts` and `test/poller-liveness.test.ts`.

- **Helpers** that register when a bwrap backend exists (critic, plan-gate reviewer, pr-critic,
  doc-agent, maintain, plugin runs) detect completion through process liveness and verdict files.
  With the record gone after exit they read dead sooner, so a run without a verdict finalizes
  faster. Teardown goes through the tab ledger and the tab label, which survives.
- **Reapers** (`tab-reaper`, `transient-tab-reaper`, the doc-agent husk close) already handle husk
  tabs without a record. Nothing is reaped earlier or wrongly.
- **The one hazard** is a registration that lands before the typed `sh <script>` has forked. herdr
  clears it for good while claude runs: the session reads `done`, no pushes go out, a resume could
  start a second claude, and a live critic gets finalized. It never reproduced (0/52), but it would
  be permanent if hit.

**Decision: accept, with hardening.** Before the register pair, both drivers now wait up to 5 s
(`awaitPaneLeftShell` in `src/herdr.ts`) until the pane's foreground runs something other than a
shell. At the deadline they register anyway, which is the pre-0.9.2 behaviour. Covered by
`test/herdr-075.test.ts` and `test/herdr-socket-075.test.ts`; L11 keeps measuring the behaviour on
every future bump.

### Release-note changes behind unchanged flags

- **New panes set `TERM_PROGRAM=herdr` and stop inheriting terminal-session IDs and Claude Code
  markers (herdr #4104).** No consumer. Every spawn carries its whole environment in the wrapped
  argv (the `env …` shim, or `bwrap --setenv`), and nothing in `src/` reads `TERM_PROGRAM` or those
  markers.
- **Closing a workspace's last tab asks for confirmation (herdr #4379, #4409).** TUI only. L5 shows
  the API close unchanged (`closed-workspace-destroyed` on both), which the #2056 last-tab guard
  already handles.
- **Event subscriptions deliver bursts in full; a lagging reader gets `events_lost` (herdr #4178,
  #4225).** No consumer. Shepherd subscribes to no herdr events.
- **Socket error responses keep the request ID (herdr #4344).** No consumer. `HerdrSocketClient`
  opens one connection per request, reads its single reply and never correlates by ID.
- **An agent's first task counts as `done` even when it started with a prompt (herdr #3338).** A
  trusted session's first turn now ends on `done` rather than possibly `idle`. `handleDoneEdge`
  (usage-halt detection, the Stop↔done window) therefore also runs on turn one, the same path every
  later turn already takes.
- **After `herdr update`, herdr lists servers still on the old version.** The in-app updater only
  tees `herdr update --handoff` output into its log and modal. It reads the outcome from the exit
  code and the runtime probe, not from the text.
- **Four fixes with no consumer, or only upside:**
  - the API socket survives a transient error (#4601), which only removes a failure mode;
  - `worktree open` no longer takes over the repository's workspace (#4293);
  - `session attach` without a terminal explains itself (#4393);
  - restored agents start 100 ms apart (#4102).

  Shepherd calls neither `worktree open` nor `session attach`, and it does not rely on herdr's
  resume table for its own sessions.

### Fixtures, CLI reference and floors

- **Fixtures:** `gen:herdr-fixtures`, captured against an isolated 0.9.2 server with a populated
  workspace, yields the same four methods with identical `type` and `resultKeys`, so the committed
  manifest is unchanged.
- **CLI reference:** the regenerated pages differ only in their version stamp.
- **Floors unchanged:** `HERDR_LAST_FULL_SANDBOX_STATUS_VERSION` stays 0.7.4 on L7's evidence
  (`idle` still lands on `done`). The external-registration (0.7.5) and first-pane-control (0.7.3)
  floors are untouched.
- **Protocol:** it stayed 22, which is already allowlisted.

## Opportunities (follow-ups, not part of this bump)

- **Report `resume_argv` for sandboxed sessions (herdr #4687).** herdr would then reopen a
  sandboxed session's exact command after a server restart. Today herdr does not restore such a
  session at all.
- **`terminal.mouse` in `terminal session control` (herdr #4685).** A building block for the
  socket terminal's missing mouse support, one of the reasons it stays default-OFF (`src/config.ts`).
- **`pane.clear`** could back a "clear terminal" action.
- **Pre-existing: `resume()` leaves the old tab behind** when no live agent matched (the teardown
  is `if (agent) … stop`). This was already true for trusted sessions and now holds for sandboxed
  ones too.
